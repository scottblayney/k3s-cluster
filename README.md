# k3s-cluster

GitOps configuration for my home k3s cluster, reconciled by [Flux](https://fluxcd.io). Everything in the cluster should be changed by committing here; Flux applies it.

## Layout

```
clusters/staging/        Flux entrypoint for the cluster
  flux-system/           Flux components and Git source (gotk-*.yaml, generated by bootstrap)
  infrastructure.yaml    Kustomizations: infra-controllers, infra-configs
  apps.yaml              Kustomization: apps (depends on infra-controllers, SOPS decryption)
  .sops.yaml             SOPS/age rules for encrypting secrets
infrastructure/
  controllers/           Cluster-wide components
    rook-ceph/             Ceph storage (CephFS StorageClass `rook-cephfs`)
    nvidia-device-plugin/  GPU support
    system-upgrade-controller/
  configs/
    system-upgrade-plans/  Automatic k3s upgrades (server and agent, stable channel)
apps/
  base/<app>/            Environment-agnostic manifests
  staging/<app>/         Overlay: pulls in base, adds Cloudflare tunnel and SOPS secrets
```

## Reconciliation order

1. `infra-controllers` (storage, GPU, upgrade controller)
2. `infra-configs` (upgrade plans), after controllers
3. `apps`, after controllers

## Ingress

Public apps are exposed through Cloudflare Tunnels, not an ingress controller. Each app overlay in `apps/staging/<app>/` has a `cloudflared` Deployment, a ConfigMap mapping hostnames to Services, and a SOPS-encrypted `tunnel-credentials` Secret.

To add a tunnel for a new app:

```sh
cloudflared tunnel create <name>
cloudflared tunnel route dns <name> <hostname>
```

Put the generated credentials JSON in a Secret, encrypt it (below), and point the ConfigMap's `tunnel:` and `ingress:` at it.

## Secrets

Secrets are encrypted with [SOPS](https://github.com/getsops/sops) and age. `clusters/staging/.sops.yaml` encrypts the `data` and `stringData` fields of any YAML file. Flux decrypts them with the `sops-age` Secret in `flux-system`.

```sh
sops --encrypt --in-place apps/staging/<app>/<secret>.yaml
```

Never commit a Secret before encrypting it. Check for a `sops:` block in the file first.

The age private key is **not** in this repo. If the cluster is rebuilt, recreate the Secret:

```sh
kubectl create secret generic sops-age -n flux-system \
  --from-file=age.agekey=<path-to-age-key>
```

## Adding an app

1. Create `apps/base/<app>/` with a `namespace.yaml`, workloads, and a `kustomization.yaml`.
2. Create `apps/staging/<app>/kustomization.yaml` that includes the base, plus the tunnel and secrets if it needs public access.
3. Add `apps/staging/<app>` to the `apps` Kustomization's path if it isn't discovered automatically, then commit and push.

## Operations

```sh
flux get kustomizations -A              # overall status
flux get sources git -A                 # is the Git source healthy?
flux reconcile kustomization apps --with-source   # sync now
kubectl -n flux-system logs deploy/kustomize-controller | tail -50
```

If `apps` is failing, the cause is usually a bad manifest (the whole Kustomization fails on one invalid object) or a missing `sops-age` Secret.

## Storage

| StorageClass | Use |
| --- | --- |
| `local-path` | Single-node, node-local volumes (Ollama models, Open WebUI) |
| `rook-cephfs` | Replicated CephFS, `reclaimPolicy: Retain` |

## Upgrades

k3s is upgraded automatically by system-upgrade-controller following the `stable` channel. Server nodes upgrade one at a time and are cordoned first. Agent upgrade jobs tolerate the GPU taint on `kubert`.
